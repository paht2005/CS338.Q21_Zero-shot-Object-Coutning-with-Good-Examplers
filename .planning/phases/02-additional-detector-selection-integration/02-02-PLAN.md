<!-- Negative exemplars are patches of things that look similar but are NOT the target class -->
<!-- Binary classifier filter for negative: keep patches where prob_label_1 < 0.5 (inverted from pos) -->

From grounding_neg.py — negative exemplar logic:
  - Query detector with negative class names (e.g., "leaf", "petiole" for "apple")
  - For Rich Prompt mode: use prompt_map[img_name]["negative_descriptions"]
  - Filter: is_negative_patch() — classifier prob_label_1 < 0.5 (inverse of positive)
  - CLIP re-rank by LOWEST score to the target class (pick worst matches = best negatives)
  - Keep top_k negative patches

From annotation_FSC147_neg.json format:
{
  "7.jpg": {
    "H": 384,
    "W": 512,
    "boxes": [[x, y, w, h], ...]
  }
}

  <action>
Create code/source-code/owlv2_neg.py by adapting owlv2_pos.py with the following changes:

1. The module docstring says "negative exemplar generator".

2. `is_negative_patch(patch, classifier, preprocess, threshold=0.5)`:
   - Inverted logic: return True when `prob_label_1 < threshold`
   (patch is likely NOT the target class = good negative exemplar)

3. In the main loop, build negative queries:
   - If `--prompt` and img_name in prompt_map:
     `queries = prompt_map[img_name].get("negative_descriptions", [])`
     Fall back to `[f"not {singular}", f"background near {singular}"]` if empty.
   - Without `--prompt`:
     `queries = [f"not {singular}", f"background near {singular}", f"similar to {singular}"]`

4. Filter step uses `is_negative_patch()` instead of `is_valid_patch()`.

5. CLIP re-ranking: sort by score ASCENDING (lowest similarity to target = best negative).
   `scored.sort(key=lambda t: t[0])   # ascending = worst match first`

6. Output file argument: `--output_file` defaults suggest
   `./data/FSC147/annotation_FSC147_neg_owlv2.json` (comment only, no hardcode).

7. All other logic (arg parsing, split loading, class_map loading, model loading) is identical
   to owlv2_pos.py.
